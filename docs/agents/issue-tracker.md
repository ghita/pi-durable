# Issue tracker

- **Repository:** `ghita/pi-durable`
- **Canonical URL:** https://github.com/ghita/pi-durable
- **Tracker:** GitHub Issues; use the `gh` CLI.
- Draft implementation tickets and get the user's approval of the exact breakdown before creating or materially changing issues. Approval of a breakdown authorizes publication of that breakdown only.
- Represent blockers with GitHub's native issue dependency relationships when supported by this repository/account and available tooling. Otherwise include `Blocked by: #<number>` in each dependent issue body.
- Use the `ready-for-agent` label for approved implementation tickets. If it is missing, ask before creating it.
- Do not close or modify a source/parent issue. When a parent exists, create proposed tickets as sub-issues if supported; otherwise link the parent in each ticket body.
- Do not include secrets, credentials, or private data in issue titles or bodies.
